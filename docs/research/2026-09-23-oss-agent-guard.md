# OSS 조사 에이전트의 GitHub 쓰기 경계

## 적용 범위

이 문서는 #197의 적용 범위를 결정한다. `claude-profile1`과
`claude-profile2`는 인증 계정이며, 계정 설정이나 일반 Codex의 전역 규칙을
조사 정책으로 취급하지 않는다. 조사 워커를 시작하는 경로에서 권한을 제한한다.

조사 워커는 파일 읽기 도구만 받는다. 셸·코드 실행·웹 요청·브라우저·MCP·
하위 에이전트 도구는 받지 않는다. GitHub에서 데이터를 가져오는 단계는
검토된 수집 스크립트를 조정자가 실행하고, 워커에게는 그 결과 파일만 준다.
이 방식에서는 워커가 GitHub에 이슈·PR·댓글을 올릴 실행 경로가 없다.

## Codex 결정

현재 `~/.codex/rules/default.rules`에는 과거에 누적된 `allow` 규칙이 있다.
2026-09-23 실측: 688개 전부 `allow`다. 직접 GitHub 쓰기 명령 8개,
범용 `gh api` 1개, `git push` 2개가 있으며 셸 또는 `env` 규칙은 148개다.
`python`·`node`·`curl` 등의 코드·네트워크 실행 규칙도 62개다.
이 숫자는 `python3 dot_local/bin/executable_audit-codex-rules`로 다시 확인할
수 있다. 도구의 분류는 감사를 돕는 목록이지 안전 판정이 아니다.

감사 도구는 규칙 파일을 읽기만 한다. 규칙·프로필·설정을 쓰지 않으며 전역
차단을 설치하지 않는다. 기본 출력은 결정별·분류별 개수와 직접 쓰기 위험
규칙의 개수만 담고, 규칙 pattern 원문은 담지 않는다. 원문에는 토큰이 들어
있을 수 있기 때문이다. 원문이 필요하면 `--json`을 명시해야 하며, 이때 출력에
`raw_rules_included: true`와 경고가 붙는다. 규칙 형식이 어긋나거나 `decision`이
문자열이 아니면 traceback 대신 해당 줄 번호를 알리고 종료 코드 2로 멈춘다.

Codex의 `allow`는 샌드박스 밖 실행을 허용한다. 별도 `forbidden` 규칙은
직접 호출을 막지만, `env`, 셸 문자열, 스크립트 내부의 호출까지 완전하게
통제하지 않는다. 따라서 조사 워커에는 Codex를 배정하지 않는다.
일반 Codex 규칙과 Claude·agy의 사용자 설정은 이 작업에서 수정하지 않는다.
전역 허용 규칙의 정리는 별도 감사 대상으로 남는다.

## 남은 경계

이 제한은 특정 조사 워커를 시작하는 경로에만 적용된다. 감사 도구는 이
제한을 만들지 않으며 현황을 보고할 뿐이다. 사용자가 일반 Claude·Codex
세션을 직접 시작하는 경우까지 통제하지 않는다. 수집 스크립트 자체의
GitHub 요청을 읽기 전용으로 제한하는 작업은 #192에서 다룬다.

`claude-profile1`·`claude-profile2`를 고르는 것만으로는 권한이 제한되지
않는다. Orca의 기본 `worker-start --agent claude`는 권한 우회 모드로
실행될 수 있으므로 조사에는 사용하지 않는다.
