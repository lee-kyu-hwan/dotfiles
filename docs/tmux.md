# tmux 키맵 & 치트시트

Prefix 키: `Ctrl+B` (macOS에서는 자동으로 영문 전환 후 prefix 테이블 진입)

`★` = 커스텀 키맵 (chezmoi로 관리, `dot_tmux.conf.tmpl`에 정의)

## 커스텀 키맵

### 패널 분할 & 기본 조작

| 키 | 기능 | 구분 |
|----|------|------|
| `prefix` → `\|` | 수직 분할 (현재 경로 유지) | ★ |
| `prefix` → `-` | 수평 분할 (현재 경로 유지) | ★ |
| `prefix` → `r` | 설정 리로드 (`tmux.conf` 재적용) | ★ |
| `prefix` → `=` | 패인 개수별 레이아웃 정렬 (2개는 좌우, 그 외 스택) | ★ |

> 기본 분할 키 `%`/`"`도 여전히 동작하지만, `|`/`-`가 더 직관적입니다.
>
> `prefix → =`는 패인 개수에 맞춰 레이아웃을 정렬합니다. 2개는 좌우로 나란히, 3개는 좌 1개 + 우 상하 2개(workmux 기본 배치)로 두고, 4개부터는 **한 행에 최대 3개씩, 아래부터 쌓습니다**. 6개까지는 2행으로 균등 분배(위 행 ≤ 아래 행), 7개부터는 아래 행을 3개씩 채우고 나머지를 맨 위에 둡니다:
>
> | 패인 수 | 레이아웃 | 패인 수 | 레이아웃 |
> |---|---|---|---|
> | 2 | 좌우 균등 (둘 다 전체 높이) | 7 | `1 + 3 + 3` |
> | 3 | 좌 1개(전체 높이) + 우 상하 2개 | 8 | `2 + 3 + 3` |
> | 4 | `2 + 2` | 9 | `3 + 3 + 3` |
> | 5 | `2 + 3` | 10 | `1 + 3 + 3 + 3` |
> | 6 | `3 + 3` | … | … |
>
> `a + b` 표기는 **위→아래 행별 패인 수**입니다 (`2 + 3` = 위 행 2개, 아래 행 3개).
>
> 정렬 후 패인은 **패인 인덱스 순서**(`prefix → ㅂ`로 보이는 번호 순)대로 왼쪽→오른쪽, 위→아래로 배치됩니다. 화면상의 읽기 순서가 인덱스 순서와 다른 상태(예: `split-window -b`로 만든 배치)였다면 정렬 후 위치가 바뀝니다.
>
> 남는 칸은 항상 왼쪽·위 패인이 가져갑니다. 패인 사이 구분선이 1칸을 쓰기 때문에 가용 폭이 `창 너비 - 구분선 수`가 되고, 나누어떨어지지 않으면 1칸 차이가 납니다 — **개수와 무관하게 공통**입니다 (120칼럼에서 2개는 `60`/`59`, 3개도 `60`/`59`, 4개의 각 행도 `60`/`59`).
>
> 전부 `~/.local/bin/tmux-stack-layout` 스크립트가 패인 개수에 맞춰 레이아웃 문자열을 동적으로 생성합니다(`dot_local/bin/`로 관리). 2개의 결과는 tmux 내장 `even-horizontal`과 같지만 내장을 쓰지 않습니다 — 문자열은 셀 수가 고정돼 있어 읽은 뒤 패인이 **늘면** `have N panes but need M`으로 거부되는 반면, 내장은 적용 시점의 창 상태를 그대로 따라가 그 변화를 조용히 삼킵니다. (패인 수가 같고 ID만 다르거나 패인이 줄어든 경우까지 막아 주지는 않습니다.)
>
> **floating 패인**(`prefix → *`의 `new-pane`)이 있으면 정렬하지 않고 상태바에 알립니다. `select-layout`으로는 floating을 남겨둔 채 타일 패인만 정렬할 수 없어서(그대로 두면 floating이 타일로 흡수됩니다), 띄워 둔 창을 말없이 바꾸는 대신 거부합니다. floating 패인을 닫고 다시 누르면 됩니다.

### 윈도우 관리

| 키 | 기능 | 구분 |
|----|------|------|
| `Shift+←` / `Shift+→` | 이전/다음 윈도우 (prefix 불필요) | ★ |
| `Ctrl+Shift+←` / `Ctrl+Shift+→` | 윈도우 순서 왼쪽/오른쪽 이동 | ★ |
| `prefix` → `R` | 윈도우 번호 즉시 재정렬 (빈 번호 메우기) | ★ |

> `renumber-windows on`이 켜져 있어 **윈도우를 닫으면 빈 번호가 자동으로 메워집니다** (예: `0,1,4` → `0,1,2`). `prefix → R`은 닫지 않고도 즉시 재정렬하는 수동 트리거입니다. base-index가 0이라 번호는 0부터 매겨집니다.

### Git / GitHub

| 키 | 기능 | 구분 |
|----|------|------|
| `prefix` → `P` | 현재 패인 브랜치의 PR을 브라우저로 열기 | ★ |

> `~/.local/bin/tmux-open-pr`이 해당 패인의 경로에서 `gh pr view --web`을 실행합니다(`dot_local/bin/`으로 관리). 인자가 없으면 gh가 현재 브랜치에 연결된 PR을 찾아 기본 브라우저로 엽니다.
>
> 소문자 `prefix → p`는 tmux 기본인 `previous-window` 그대로이고, 비어 있던 대문자 `P`를 씁니다.
>
> **대상 패인과 클라이언트를 바인딩이 `#{pane_id}`·`#{client_tty}`로 넘깁니다.** gh는 네트워크 왕복을 하므로 키를 누른 뒤 결과가 나오기까지 0.5~2초가 빕니다. 그 사이에 창이나 클라이언트가 바뀌면 대상이 흔들리는 것을 격리 서버 + 실제 attach 클라이언트로 확인했습니다.
>
> | 굳히지 않으면 | 실측 결과 |
> |---|---|
> | 스크립트가 읽는 경로 | tmux는 `run-shell` 자식에게 `TMUX`는 주지만 **`TMUX_PANE`은 주지 않아**, `-t` 없이 tmux를 부르면 세션의 현재 창 활성 패인으로 해석됨 |
> | 메시지가 뜨는 곳 | `display-message`에 `-c`가 없으면 그 세션의 **가장 최근 클라이언트**로 감 — 지연 중 다른 터미널을 건드리자 그쪽에 떴음 |
>
> 바인딩의 `-t ':'`는 알림 자체가 실패했을 때 열리는 view-mode의 대상을 못 박습니다. `-t`에 `#{pane_id}`는 쓸 수 없습니다 — **`-t`는 포맷을 확장하지 않아** 타깃이 잡히지 않고, 그러면 `run-shell`이 저장해 둔 패인이 없어 완료 시점의 현재 패인으로 흘러갑니다(실측: 지연 중 창을 바꾸자 옮겨간 창이 덮임). 리터럴 `:`는 시작 시점에 현재 창의 활성 패인으로 해석돼 고정됩니다(실측: 창을 바꿔도 누른 창이 덮임). 경로 대신 ID를 넘기는 것은 `%12` 꼴이라 작은따옴표가 든 경로에서도 명령 문자열이 깨지지 않기 때문입니다.
>
> **실패하면 상태바에 사유가 4초간 뜨고, 화면은 뺏지 않습니다.** `run-shell -b`는 자식이 **출력을 내거나 0이 아닌 코드로 끝나면** 대상 패인을 `view-mode`로 전환합니다(실측: 출력 없이 `exit 1` → 전환, 출력 있고 `exit 0` → 전환, 출력 없이 `exit 0` → 전환 없음). PR이 없는 것처럼 흔한 실패까지 화면을 덮는 것은 과하므로, 상태바로 알리는 데 성공하면 출력 없이 `exit 0`으로 끝냅니다. 알리는 것 자체가 실패했을 때만 비정상 종료해 view-mode를 최후의 신호로 남깁니다.
>
> 사유는 gh의 첫 줄을 그대로 전달합니다 — 저장소 아님, PR 없음, 미인증이 각각 다른 문구로 나옵니다. `display-time`이 750ms라 이 메시지만 4초로 늘려 잡았습니다.
>
> 문구는 `#`→`##`, `%`→`%%`로 **이스케이프해서** 넘깁니다. tmux는 메시지를 FORMATS와 strftime으로 확장하므로(실측: `%999` → `999`, `#{pane_id}` → `%1`, `#H` → 호스트명) 경로나 브랜치명에 든 `#`·`%`가 그대로면 망가집니다. 확장을 끄는 `-l`은 쓰지 않습니다 — tmux **3.4에서 추가된** 옵션이라 Debian 12(3.3a)·Ubuntu 22.04(3.2a)에서는 호출 자체가 `rc=1`로 실패합니다. 이스케이프는 결과가 `-l`과 동일하고(두 방식의 출력이 같음을 확인) 버전을 가리지 않습니다.
>
> **알림 호출이 실패하면 실패로 봅니다.** `display-message`의 종료코드를 그대로 씁니다. 삼키면 알림이 통째로 사라진 것을 성공으로 오판해, 출력 없이 `exit 0`으로 끝나며 상태바도 view-mode도 없는 **완전한 무음 실패**가 됩니다. 실제로 걸리는 경로가 있습니다 — 지연 시간을 정하는 `-d`는 tmux **3.2에서 추가된** 옵션이라(`CHANGES FROM 3.1c TO 3.2`) 그보다 낮은 배포판 tmux(Debian 11 3.1c, Ubuntu 20.04 3.0a, RHEL/Rocky 8 2.7)에서는 이 호출이 실패하고, `setup.sh`는 Linux에서 배포판 tmux를 그대로 설치합니다. 그래서 `-d` 없이 한 번 더 시도하고(750ms로 짧게 뜨지만 무음보다 낫습니다), 그마저 실패하면 아래 view-mode 폴백으로 넘어갑니다.
>
> **알림 상대는 키를 누른 그 클라이언트 하나뿐입니다.** 그 클라이언트가 사라졌을 때 다른 클라이언트를 골라 보내는 폴백은 두지 않습니다 — 필요가 없고, 두면 경합만 생깁니다.
>
> - 필요가 없습니다: 같은 세션의 다른 클라이언트는 **같은 창을 보고 있어서** 아래 view-mode를 그대로 읽습니다(실측: 한 세션에 클라이언트 2개를 붙이고 view-mode를 열자 양쪽 화면에 사유가 다 보였습니다). 다른 세션의 클라이언트는 애초에 알릴 상대가 아닙니다.
> - 경합만 생깁니다: 후보를 고르는 순간 "고른 뒤 detach하면?", "고른 뒤 세션을 옮기면?"이 따라붙는데, tmux는 도착 여부를 알려주지 않아 어느 쪽도 닫을 수 없습니다.
>
> **정확히 무엇이 보장되는가.** 상대는 *세션*이 아니라 **키를 누른 터미널(TTY)** 로 식별됩니다. 그 터미널이 그새 다른 세션으로 재attach했다면 메시지는 세션이 아니라 **터미널을 따라갑니다**(실측: A에서 누른 뒤 같은 TTY가 B로 재attach하자 B 화면에 떴고, A 패인에는 기록이 남지 않았습니다). tmux 세션은 모두 같은 사용자 것이고 그 터미널이 곧 사용자가 앉아 있는 자리이므로 이 동작을 그대로 둡니다 — 막으면 그 경우 사용자는 아무 메시지도 못 받고, 볼 일 없는 패인에 기록만 남습니다. 따라서 view-mode 기록은 "그 TTY가 **아무 세션에도 붙어 있지 않을 때**"만 보장됩니다.
>
> **알림은 최대 한 번 보냅니다.** 보낸 뒤 다시 확인해 재전송하는 방식은 쓰지 않습니다 — 정상 도착 직후 detach하면 같은 문구를 한 번 더 띄웁니다. 중복과 유실 중 하나를 골라야 하고, 중복을 버렸습니다. 그래서 "확인 직후 detach"에서는 도착이 **0회**가 되고("정확히 한 번"이 아닌 이유), 그때는 브라우저가 뜨지 않는 것으로 알아챌 수 있습니다. `-c`에 사라진 클라이언트를 줘도 tmux는 아무것도 표시하지 않고 `rc=0`을 돌려주므로(실측), 그 경우의 판정은 종료코드가 아니라 `list-clients`로 합니다.
>
> **키를 누른 클라이언트가 없고 대상 패인이 살아 있으면 view-mode로 남깁니다.** 사유를 stdout으로 내보내고 비정상 종료해, `-t ':'`로 못 박은 패인에 view-mode로 남깁니다 — 다시 attach했을 때 사유가 그대로 화면에 있습니다(실측). SSH가 끊긴 채 키가 눌린 경우가 이 경로입니다. **패인이 이미 닫혔으면 조용히 `exit 0`합니다** — `run-shell`이 저장하는 것은 패인 참조가 아니라 ID뿐이라, 그 패인이 없으면 tmux가 가장 최근 세션의 활성 패인으로 폴백해 **무관한 창을 덮습니다**(실측: 대상 패인을 닫자 다른 세션의 패인이 view-mode가 됐습니다). 남길 곳이 사라진 마당에 남의 화면을 뺏지는 않습니다. 이때는 브라우저가 뜨지 않는 것이 유일한 신호입니다.
>
> **gh 는 20초 + 유예 2초의 하드 상한으로 끊고, 그 프로세스 그룹까지 거둡니다.** gh에는 자체 시간 제한이 없어(옵션도 환경변수도 없고 내부 http.Client의 Timeout 기본값이 0) 응답을 멈춘 프록시나 GHE를 만나면 브라우저도 오류도 없이 영원히 매달립니다 — 무응답 gh를 흉내내고 3번 누르자 스크립트와 gh가 3벌 그대로 쌓였습니다. macOS 기본 bash 3.2에는 `wait -n`이 없고 `timeout`(coreutils)도 기본 설치가 아니라 감시 프로세스로 상한을 둡니다.
>
> gh를 **자기 프로세스 그룹에서** 띄웁니다(`set -m`). gh는 브라우저 런처를 자식으로 실행하고 그 종료를 기다리므로 gh만 죽이면 런처가 고아로 남습니다(실측: 멈추는 `GH_BROWSER`를 지정하고 gh를 죽이자 런처가 살아남았고, 그룹으로 죽이자 0개가 됐습니다). 시간 초과 시 그룹에 **TERM → 유예 → KILL** 순으로 보내고, 감시자가 그 승격을 **끝낸 뒤에** 본문이 종료합니다.
>
> **TERM만으로는 상한이 상한이 아니었습니다.** 그룹 멤버가 TERM을 무시하면 `wait`이 영원히 돌아오지 않고(실측: 상한 2초로 줄여 재현했더니 31초까지 반환 없음 — 가짜 gh가 스스로 끝난 시각입니다), gh 자신은 TERM에 죽어도 TERM을 무시하는 자손은 `PPID=1` 고아로 남았습니다(실측). KILL 승격을 두어 상한을 `20 + 2`초로 확정했습니다.
>
> **승격이 무관한 프로세스 그룹을 맞히지 않는 이유.** 그룹에 멤버가 하나라도 살아 있으면 PGID는 재사용되지 않습니다(POSIX). 실측: gh를 reap한 뒤에도 TERM을 무시한 자손이 살아 있는 동안 `kill -0 -- -PGID`가 성공했고, 그 상태에서 KILL이 정확히 그 자손만 정리했습니다. 즉 승격이 **필요한** 경우가 곧 그룹이 점유된 경우이므로, 쏘기 직전에 점유를 확인하면 남의 그룹에 닿을 수 없습니다. 반대로 그룹이 비어 있으면 확인이 실패해 아무것도 쏘지 않습니다(거둘 대상도 없습니다). 이전 판의 "`wait`이 reap했으니 PID(=PGID)가 해방됐다"는 설명은 그룹이 **완전히 빈** 경우에만 참이고, 그 경우엔 승격할 이유도 없습니다.
>
> **성공했을 때는 gh 그룹을 건드리지 않습니다.** 그때 그룹에 남아 있을 수 있는 것은 방금 띄운 브라우저이고, 고아 하나를 막으려 사용자의 브라우저를 죽이는 것이 훨씬 나쁩니다.
>
> 표식은 TERM보다 **먼저** 씁니다(나중에 쓰면 gh가 먼저 죽어 시간 초과를 놓칩니다). 감시자는 자기 `sleep` 자식을 **자기가** 거둡니다(내부 TERM 트랩) — 부모가 `pkill -P`로 찾아 죽이는 방식은 busybox `pkill`에 `-P`가 없고, 부모가 먼저 사라지면 애초에 찾을 수도 없습니다(실측: `sleep`이 상한 시간만큼 고아로 남았습니다).
>
> **helper 자체가 HUP/INT/TERM으로 죽을 때도 거둡니다.** 트랩이 임시 파일만 지우던 동안에는 helper에 TERM을 보내면 gh(`PPID=1`, 독립 PGID)·감시자 서브셸·그 `sleep`이 셋 다 고아로 남고 임시 파일도 유출됐습니다(실측). `tmux kill-server`도 같은 경로입니다(실측: `run-shell` 자식은 정리되고 gh만 남았습니다). 이제 한 번만 도는 정리 함수가 EXIT와 HUP/INT/TERM에 함께 걸려, `sleep` → 감시자 → gh 그룹 순서로 종료하고 reap합니다. 이 경로는 보여 줄 사유가 없어 **출력 없이 `exit 0`**으로 끝냅니다 — 0이 아닌 코드는 빈 view-mode로 패인을 덮칠 뿐입니다.
>
> 위 네 가지(무음 실패, 하드 상한, 그룹 KILL, 신호 정리)는 `tests/tmux-open-pr.test.sh`가 tmux 스텁과 가짜 gh로 고정합니다. 실제 tmux가 필요한 view-mode 규약만 격리 소켓(`tmux -L …`)에서 확인하고, 기본 소켓은 건드리지 않습니다.
>
> `set -m`의 작업 제어 알림은 stderr로 나가는데, 스크립트는 stderr를 쓰지 않으므로 통째로 버립니다. stderr만으로는 view-mode가 열리지 않지만(실측: stderr + `exit 0` → 전환 없음) `exit 1` 경로에서 사유와 섞이기 때문입니다.
>
> 성공했을 때는 아무것도 띄우지 않습니다. 브라우저가 뜨는 것 자체가 피드백입니다.
>
> **전제: `gh` 가 설치돼 있어야 합니다.** macOS는 Brewfile이 처리하고, Linux는 `setup.sh`가 apt/dnf로 설치를 시도합니다. 배포판·릴리스에 따라 저장소에 `gh`가 없을 수 있는데, 그때는 설치가 실패해도 나머지 설정은 계속 진행되고 이 단축키만 "gh(GitHub CLI)를 찾을 수 없습니다"로 끝납니다 — [gh Linux 설치 문서](https://github.com/cli/cli/blob/trunk/docs/install_linux.md)를 따라 직접 넣으면 동작합니다.
>
> 헤드리스 환경(server 머신)에서는 열 브라우저가 없어 gh의 실패 메시지가 그대로 상태바에 나옵니다. 바인딩 자체는 OS 분기 없이 모든 머신에 배포합니다.

### 한글 IME 호환 (macOS only)

> macOS에서 한글 입력 중 `Ctrl+B`를 누르면 macism으로 자동 영문 전환 후 prefix가 작동합니다.
> 창/패인 전환 시에도 자동으로 영문 입력으로 초기화됩니다.

| 키 | 기능 | 구분 |
|----|------|------|
| `Ctrl+B` | prefix (macOS: 영문 전환 + prefix) | ★ |
| `prefix` → `Ctrl+B` | 리터럴 `Ctrl+B` 전송 (중첩 tmux에 prefix 전달) | ★ |

> vim-tmux-navigator가 `Ctrl+L`을 "오른쪽 이동"으로 가져가므로, 화면 클리어는 `prefix + Ctrl+L`로 옮겼습니다.
>
> ⚠️ 단, 플러그인은 보상으로 `prefix C-l`을 `send-keys C-l`(단순 클리어)에 **자동 매핑**하는데, 이게 우리의 `clear-history`(스크롤백 클리어) 바인딩을 덮어쓴다. 이를 막기 위해 플러그인 로드 전에 자동 매핑을 비활성화한다:
> ```tmux
> set -g @vim_navigator_prefix_mapping_clear_screen ""
> ```
> 이 한 줄이 있어야 `prefix + Ctrl+L`의 스크롤백 클리어가 실제로 동작한다. ([vim-tmux-navigator Issue #9](https://github.com/christoomey/vim-tmux-navigator/issues/9))

### 세션 복원

TPM으로 `tmux-resurrect`, `tmux-continuum`을 사용합니다.

| 항목 | 설정 |
|------|------|
| pane 내용 저장 | 켜짐 |
| 저장 위치 | `~/.local/share/tmux/resurrect` |
| 자동 저장 주기 | 15분 |
| tmux 시작 시 자동 복원 | 켜짐 |

이름 없이 만들어진 `0`번 세션은 `session-created` 훅이 `1-main`으로 개명합니다. 단
`1-main`이 이미 있으면 이 개명은 **조용히 실패**하고(`duplicate session`, 훅 경로에서는
오류가 표시되지 않음) 세션은 `0`이라는 이름으로 남습니다. `.zshrc`가 항상 `-s 1-main`을
지정하므로 통상 흐름에서는 훅이 발동하지 않고, 인수 없이 `tmux`를 직접 실행했을 때만
이 경로를 타게 됩니다. 규칙 밖 이름(`0`, `1`)이 생기면 `prefix → $`로 직접 고칩니다.

### 세션 이름 규칙

세션명은 `{순번}-{이름}` 형식을 씁니다 (`1-main`, `2-review`, `3-personal`,
`4-eslint`, `5-quick`). `prefix → s`가 `choose-tree -Zs -O name`으로 바인딩되어
있어 목록이 **이름순**으로 나오기 때문입니다. tmux의 기본 정렬은 `index`(세션
생성 순)라서 접두사가 없으면 만든 순서대로 섞여 나옵니다.

| 키 | 기능 |
|----|------|
| `prefix` → `s` | 세션 목록 (이름순 고정) |
| 목록 안에서 `O` | 정렬 필드 순환 (`index`/`name`/`activity`/`z`) — 일회성 |
| 목록 안에서 `r` | 정렬 역순 — 일회성 |
| `prefix` → `$` | 세션 이름 변경 |

> 이름순 정렬은 자연 정렬이 아니라 바이트 비교입니다. 그래서 세션이 10개를 넘으면
> `10-`이 `2-` **앞에** 오면서 순번의 의미가 깨집니다. 9개까지는 문제가 없고, 그
> 이상 쓰게 되면 `01-`/`02-` 제로패딩으로 바꿔야 합니다.

> `prefix → w`(윈도우 트리)는 `index` 정렬을 유지합니다. `-O name`은 트리 전체에
> 적용돼 세션 안의 윈도우까지 이름순으로 섞이는데, 윈도우는 번호 순이 맞습니다.
> 대신 `prefix → w`의 **세션 행도 생성 순으로 남습니다** — 순번 접두사는 그쪽
> 목록에서는 순서에 영향을 주지 않습니다.

> 세션 이름을 바꿀 때 함께 고쳐야 하는 곳: `.tmux.conf`의 `session-created` 훅
> (`rename-session`의 대상 이름 — 세션명을 자동으로 결정하는 1차 지점), `~/.zshrc`의
> `exec tmux new-session -A -s 1-main`, `create-worktree`·`move-window-to-session`
> 스킬의 `--parent-session`, workmux의 `workmux.worktree.*.window-session` git
> config, 그리고 이 문서.

### 기존 세션 개명 (구 이름이 남은 머신)

구 이름 세션(`main`, `review`, `personal`, `eslint`, `quick`)이 살아 있는 머신에서 새
설정을 적용하면, `-A`는 **이름이 정확히 일치할 때만** 붙기 때문에 빈 `1-main` 세션이
새로 생기고 터미널은 거기에 붙습니다. 기존 작업은 구 이름 세션에 그대로 남고 화면에는
아무 경고가 없습니다. `.zshrc`가 이 상태를 감지해 경고는 하지만 개명은 하지 않습니다.

세션명은 세 곳에 저장되고, 하나만 고치면 나머지가 어긋납니다.

| 저장소 | 무엇의 근거인가 |
|--------|-----------------|
| tmux 서버의 세션명 | 실제 창 위치 |
| `~/.local/state/workmux/agents/*.json`의 `session_name` | 윈도우 탭의 에이전트 표시, `prefix + G`의 last-done, dashboard |
| 저장소별 `workmux.worktree.*.window-session` git config | workmux가 close/remove/open에서 창을 찾는 근거 |

세 곳을 함께 옮기고 결과를 재검증하는 스크립트가 있습니다.

```bash
tmux-migrate-session-names --dry-run               # 할 일만 출력, 아무것도 바꾸지 않음
tmux-migrate-session-names                         # 적용 (현재 저장소의 git config 포함)
tmux-migrate-session-names ~/code/foo ~/code/bar   # 저장소를 지정
```

worktree들은 `.git/config`를 공유하므로 저장소마다 한 번이면 됩니다. `jq`가 필요합니다
— macOS에는 이미 있고, Linux에서는 `apt install jq`로 넣어야 합니다.

개명은 비파괴적입니다. 대상 이름이 이미 있으면 임시 이름을 거쳐 클라이언트와 윈도우를
합치며 `kill-session`은 쓰지 않습니다 — 붙어 있는 클라이언트를 detach시키면 `.zshrc`가
`exec tmux`를 하므로 그 터미널 창이 닫히기 때문입니다.

건드리지 않는 것이 둘 있고, 스크립트가 그때마다 이유를 출력합니다.

- **다른 tmux 서버의 state** — `instance`가 다르면 우리 소관이 아닙니다.
- **이전 부팅의 state** — `workmux resurrect`의 입력입니다. 고치거나 지우면 복구가
  불가능해집니다. 복원한 뒤 스크립트를 한 번 더 돌리면 정리됩니다.

규칙에 맞는 값(`숫자-`로 시작)은 `move-window-to-session`이 의도적으로 기록한 것이므로
그대로 둡니다. 매핑에 없는 규칙 밖 값이 남아 있으면 스크립트가 실패로 보고합니다 —
어느 세션으로 옮길지는 직접 정해야 합니다.

**끝나면 `prefix + C-s`로 스냅샷을 다시 저장합니다.** 재저장하지 않으면 구 이름이 담긴
스냅샷이 복원될 때 세션이 **이중화**됩니다. resurrect의 `restore.sh`는 스냅샷의 세션명이
현재 세션과 다르면 오류 없이 `new_session`으로 새로 만들기 때문입니다. 스크립트가 실패를
보고했으면 **저장하기 전에 먼저 고칩니다** — 지금 저장하면 어긋난 상태가 스냅샷에
고착됩니다.

### 복사 모드

| 키 | 기능 |
|----|------|
| `prefix` → `[` | 복사 모드 진입 |
| `q` | 복사 모드 종료 |
| `v` | 선택 시작 (★ Vim 스타일) |
| `y` | 선택 복사 후 종료 (★ Vim 스타일) |
| `Space` | 선택 시작 (기본) |
| `Enter` | 선택 복사 (기본) |
| `prefix` → `]` | 붙여넣기 |
| `/` | 검색 |
| `n` / `N` | 다음/이전 검색 결과 |

### 기타

| 키 / 명령어 | 기능 |
|-------------|------|
| `prefix` → `t` | 시계 표시 |
| `prefix` → `:` | 명령어 모드 |
| `tmux source-file ~/.tmux.conf` | 설정 재로드 |
| `prefix` → `?` | 전체 키바인딩 목록 |
