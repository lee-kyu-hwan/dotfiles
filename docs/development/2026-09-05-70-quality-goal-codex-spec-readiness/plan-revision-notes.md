### 1. `PLAN-06` (High, blocker) — AC-84 의 판정 대상이 두 곳으로 갈렸다

**리뷰어 지적.** AC-105 의 판정 대상을 `docs/quality-goal-maintenance.md` 로 옮기면서 같은 요구사항 **R9.9** 의 짝인 AC-84 를 옮기지 않았다. 추적표 AC-84 행은 `spec.md` § Test strategy 를 가리키는데 소유 태스크 T17 의 통과 확인은 `grep -n 'Python 3.12' docs/quality-goal-maintenance.md` 를 지시했다. 게다가 T16 의 구현 단계에 그 문언을 만드는 지시가 없어, 계획대로 실행하면 판정 명령이 0건을 반환한다.

**해소.** 리뷰어가 제시한 두 갈래 중 첫째(유지보수 문서로 통일)를 택했고, **Spec 과 Plan 양쪽**을 고쳤다.

| 층 | 개정 전 | 개정 후 |

| `plan.md` 추적표 AC-84 행 | 소유 T17, `[문서]` `spec.md` § Test strategy | 소유 **T16**, `[문서]` `docs/quality-goal-maintenance.md` § 판정 명령 표 |
| T16 구현 | 세 항목(CLI 점검·표 교체·동기화) | **네 항목** — 표 바로 아래에 최소 Python 3.12 명시와 두 근거(`enterContext`, `NO TESTS RAN` 종료 코드 5)를 싣는 단계를 추가 |

**판정 대상을 `spec.md` 가 아니라 유지보수 문서로 정한 이유** — `docs/development/…/spec.md` 는 goal 이 끝나면 옮겨지거나 지워질 수 있는 일회성 산출물이라 스킬 테스트가 그것을 읽으면 CMD-1 이 영구히 깨진다. T16 이 AC-105 에 대해 이미 기록한 근거와 같다.

**소유 태스크를 T17 이 아니라 T16 으로 옮긴 이유** — 사용자 지시는 "T17 의 판정 명령이 두 근거까지 확인하게 하라" 였고 그 실질(명령이 세 가지를 모두 본다)은 지켰다. 다만 소유자를 T17 에 남기면 § Tasks 의 소유권 원칙("통과 확인을 실제로 실행할 수 있는 **가장 이른** 태스크가 소유한다")과 어긋난다 — 문언을 만드는 것이 T16 이므로 T16 이 끝난 시점에 이미 판정 가능하다. 아래 4절의 전수 대조가 이것을 `[A 생성]` 결손으로 잡았다. 그래서 소유는 T16 으로 옮기고, T17 에는 같은 명령을 회귀 확인으로 남겼다. R9.9 의 세 AC 중 AC-84·AC-105 가 같은 파일의 같은 표를 판정하게 됐고, AC-85 는 문서가 아니라 `tests/assert_python_version.py` 의 동작을 CMD-7 로 판정하므로 갈림이 아니다.

**판정 명령** — `M=docs/quality-goal-maintenance.md` 로 두고 `grep -n 'Python 3.12' "$M" && grep -n 'enterContext' "$M" && grep -nE 'NO TESTS RAN|종료 코드 5' "$M"`. 세 절을 `&&` 로 묶으므로 하나라도 0건이면 명령 전체가 비정상 종료한다. 개정 전 명령은 첫 절만 있어 두 근거의 부재를 통과시켰다.

**상호작용 판정.** 이 해소는 다른 해소의 전제를 깨지 않는다. AC-105 는 개정 전부터 같은 문서를 판정했고, T16 이 두 AC 를 함께 소유하게 되면서 오히려 한 태스크 안에서 정합이 강제된다. T17 의 착수 조건(T1~T16 완료)은 그대로이므로 회귀 재확인의 실행 가능성도 유지된다.
