## 1. AC-44 가 요구하는 것

Spec 의 문언은 다음이다.

> **AC-44** digest 대조 실패와 경로 불일치가 단계를 바꾸지 않고 사용자 보고로 이어진다는 지시가 존재한다. [문서] `references/readiness-policy.md` § digest 대조

여기에는 **서로 독립인 조건이 둘** 있다. 근거는 Spec R5.3 이 R5.1(경로 불일치)과 R5.2(digest 불일치) 두 위반을 함께 묶어 같은 처리로 규정한다는 것이다.

| 조건 | 주어 | 요구하는 효과 |
|---|---|---|
| **A** | digest 대조 실패 | `SPEC_REVIEW` 단계를 바꾸지 않는다 + 사용자에게 보고한다 |
| **B** | 심사 대상 경로 불일치 | `SPEC_REVIEW` 단계를 바꾸지 않는다 + 사용자에게 보고한다 |

둘 다 `references/readiness-policy.md` 의 `## digest 대조` 절 **안에** 있어야 한다. 절 밖(예: `## 실패 보고`)에 있는 문언은 AC-44 를 충족하지 않는다 — Spec 이 판정 절을 하나로 지정했기 때문이다.

## 2. 기존 Plan T9 의 검증 명령과 그 결함

Plan T9 의 실패 확인·통과 확인은 다음 하나를 쓴다.

```bash
sed -n '/^## digest 대조$/,/^## /p' dot_claude/skills/quality-goal/references/readiness-policy.md \
  | grep -c -e '단계를 바꾸지 않고' -e '사용자에게 보고한다'
```

통과 조건은 "2 이상" 이다. 결함이 셋이다.

1. **`grep -c` 는 매치 수가 아니라 매치된 줄 수를 센다.** 두 조건을 한 줄에 함께 적은 **정상 문서**가 1 을 내어 오탐한다.
2. **주어와 효과가 묶여 있는지 보지 않는다.** `단계를 바꾸지 않고` 와 `사용자에게 보고한다` 가 서로 다른 줄에 흩어져 있고 어느 줄도 조건 A·B 의 주어와 이어져 있지 않아도 줄 수가 2 가 되어 **오통과**한다.
3. **조건 A 와 조건 B 를 구별하지 않는다.** 조건 A 만 두 줄에 걸쳐 적혀도 2 가 나오므로 조건 B 의 누락을 잡지 못한다.

여기에 더해 T9 의 **구현 지시와 검증 명령의 문자열이 어긋난다** — 구현 지시는 "위반이 단계를 바꾸지 않고 **사용자 보고로 이어진다**는 것을 적는다" 이고, 검증 명령이 찾는 문자열은 `사용자에게 보고한다` 다. 지시를 그대로 따르면 같은 태스크의 통과 확인이 실패한다.

## 3. 보완한 검증 방법

**조건마다 독립으로 확인하고, 개수 비교를 쓰지 않는다.** 각 조건은 주어와 두 효과가 **같은 줄** 에 함께 있는지를 하나의 정규식으로 본다.

```bash
DOC=dot_claude/skills/quality-goal/references/readiness-policy.md
SECTION=$(sed -n '/^## digest 대조$/,/^## /p' "$DOC")
[ -n "$SECTION" ] || { echo "FAIL: '## digest 대조' 절이 없다"; exit 1; }

# 조건 A
printf '%s\n' "$SECTION" | grep -qE 'digest 대조 실패.*단계를 바꾸지 않고.*사용자에게 보고한다'
# 조건 B
printf '%s\n' "$SECTION" | grep -qE '경로 불일치.*단계를 바꾸지 않고.*사용자에게 보고한다'
```

두 `grep -q` 가 **각각** 종료 코드 0 이어야 AC-44 가 충족이다. 실행 가능한 형태는 `.claude/quality-state/<task-id>/plan-06/check_ac44.sh` 에 있고, 그 스크립트가 조건별로 `ok`/`FAIL` 을 출력한 뒤 하나라도 실패하면 1 로 끝난다.

- `sed` 의 절 잘라내기는 그대로 유지한다 — `## digest 대조` 헤딩에서 시작해 다음 `^## ` 헤딩 직전까지다. 시작 줄이 `^## ` 에 매치되지만 sed 범위는 시작 줄에서 끝나지 않으므로 정상 동작하고, `### ` 하위 절은 `^## ` 에 매치되지 않아 절 안에 남는다.
- 절이 파일의 마지막 절이면 EOF 까지 잘린다.
- `grep -c` 와 임계값은 쓰지 않는다. 문구의 **총개수**로는 어떤 판정도 하지 않는다.

### T9 가 써야 할 문언

검증 명령과 구현 지시의 문자열을 하나로 맞춘다. `## digest 대조` 절은 다음 두 문장을 담는다(조사·수식은 붙여도 되지만 아래 세 조각은 각 문장 안에 그 순서로 있어야 한다).

- `digest 대조 실패는 SPEC_REVIEW 단계를 바꾸지 않고 사용자에게 보고한다`
- `심사 대상 경로 불일치는 SPEC_REVIEW 단계를 바꾸지 않고 사용자에게 보고한다`

Plan T9 의 § digest 대조 구현 지시에 있는 "위반이 단계를 바꾸지 않고 **사용자 보고로 이어진다**" 는 위 문언으로 대체한다. `## 실패 보고` 문단은 Plan T9 가 정한 대로 다른 표현(`SPEC_REVIEW` 를 유지한 채 알린다)을 계속 쓰며, 그래야 절을 잘라내지 않더라도 두 절의 문자열이 겹치지 않는다.
