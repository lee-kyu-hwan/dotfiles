These are read as account-binding metadata rather than a duplicate task registry, because #111 section 5 explicitly lists `provider`, `role_profile`, `account_profile`, `account_scope`, `selection_source`, `selection_reason`, `usage_admission_status` and `binding_generation` as the metadata a task or session record carries, and because this Spec consumes rather than implements the #94/#95 registries. If #94 or #95 later defines a single authoritative store, these fields move into it rather than being duplicated.

Recorded as a follow-up for the operating documentation in T14; it changes no requirement, acceptance criterion or judgement command in the approved artifacts.
